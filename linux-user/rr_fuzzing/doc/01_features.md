# RR-Fuzz 功能特性文档

## 概述

RR-Fuzz (Record-Replay Fuzzing) 是基于QEMU用户模式的记录-重放模糊测试框架，通过捕获程序的系统调用执行轨迹，并在重放时进行参数变异来发现程序漏洞。

## 核心功能

### 1. 记录-重放机制 (Record-Replay)

#### 1.1 系统调用记录
- **完整轨迹捕获**: 记录目标程序的所有系统调用及其参数
- **智能参数解析**: 自动识别并捕获指针参数指向的数据
- **文件描述符跟踪**: 维护文件描述符的创建和使用关系
- **二进制轨迹存储**: 高效的二进制格式存储轨迹数据

#### 1.2 确定性重放
- **精确重放**: 确保重放时的系统调用行为与记录时完全一致
- **参数恢复**: 准确恢复所有系统调用参数和返回值
- **状态同步**: 保持程序执行状态的一致性

### 2. 模糊测试引擎

#### 2.1 参数变异
- **类型感知变异**: 根据系统调用类型进行智能变异
- **缓冲区替换**: 针对读写操作的数据缓冲区进行变异
- **边界值测试**: 自动生成边界值和异常值
- **随机化策略**: 支持多种随机化变异算法

#### 2.2 变异指令系统
- **FUZZ_CMD_MUTATE_ARG**: 变异特定参数值
- **FUZZ_CMD_REPLACE_BUFFER**: 替换缓冲区内容
- **批量指令执行**: 支持多个变异指令同时应用
- **灵活的指令格式**: 可扩展的变异指令结构

### 3. Fork Server 高性能执行

#### 3.1 快速重启机制
- **进程快照**: 在指定检查点创建进程快照
- **快速fork**: 避免重复的初始化开销
- **并行执行**: 支持多进程并发fuzzing

#### 3.2 状态管理
- **检查点设置**: 可配置的fork点位置
- **进程生命周期管理**: 自动管理子进程创建和销毁
- **资源清理**: 确保资源正确释放

### 4. IPC 通信机制

#### 4.1 多通道通信
- **命令管道**: 接收外部控制命令 (F/Q/S/L)
- **状态管道**: 报告执行状态和结果
- **共享内存**: 高效的数据交换通道

#### 4.2 协议定义
- **Ready状态**: Fork Server准备就绪
- **At Fork Point**: 到达fork点
- **Execution Complete**: 执行完成
- **Error报告**: 错误状态反馈

### 5. 快照管理系统

#### 5.1 进程状态捕获
- **文件描述符映射**: 保存FD状态快照
- **内存状态**: 进程内存快照（简化实现）
- **执行上下文**: 系统调用执行上下文

#### 5.2 状态恢复
- **快照恢复**: 恢复到指定检查点状态
- **增量快照**: 支持多层次的状态管理
- **自动清理**: 过期快照的自动清理机制

### 6. 配置管理系统

#### 6.1 统一配置
- **配置文件支持**: 支持配置文件和环境变量
- **分层配置**: 配置文件 → 环境变量的优先级
- **动态配置**: 运行时配置更新

#### 6.2 配置项
```
核心配置:
- enabled: 是否启用RR-Fuzz
- mode: 运行模式 (record/replay/fuzzing)
- trace_file: 轨迹文件路径

IPC配置:
- shared_memory_name: 共享内存名称
- cmd_pipe_path: 命令管道路径
- status_pipe_path: 状态管道路径
- shared_memory_size: 共享内存大小

Fork Server配置:
- fork_server_enabled: 是否启用Fork Server
- fork_point: Fork点位置

调试配置:
- debug_level: 调试级别 (0-5)
- debug_syscall: 系统调用跟踪
- debug_fd: 文件描述符跟踪
- debug_mem: 内存操作跟踪
- debug_ipc: IPC通信跟踪
- debug_perf: 性能统计
```

### 7. 调试支持系统

#### 7.1 分级调试
- **6个调试级别**: OFF/ERROR/WARN/INFO/VERBOSE/TRACE
- **模块化调试**: 按功能模块独立控制调试输出
- **性能友好**: 编译时可完全禁用调试代码

#### 7.2 调试功能
- **系统调用跟踪**: 详细的系统调用执行日志
- **FD跟踪**: 文件描述符的创建和使用追踪
- **内存操作跟踪**: 内存分配和访问记录
- **IPC通信详情**: 进程间通信的详细日志
- **性能统计**: 执行时间和资源使用统计

## 技术特色

### 1. 轻量级集成
- **QEMU集成**: 深度集成到QEMU用户模式
- **最小开销**: 对正常程序执行的影响最小
- **无侵入**: 不需要修改目标程序

### 2. 高性能设计
- **二进制轨迹**: 高效的二进制存储格式
- **内存优化**: 智能的内存管理策略
- **并发执行**: 支持多进程并发fuzzing

### 3. 可扩展架构
- **模块化设计**: 各功能模块独立可扩展
- **插件机制**: 支持自定义变异策略
- **开放接口**: 提供标准化的API接口

### 4. 跨平台支持
- **多架构支持**: 支持ARM、x86、MIPS等架构
- **Linux兼容**: 完整的Linux系统调用支持
- **构建系统**: 集成到QEMU的Meson构建系统

## 限制和注意事项

### 1. 技术限制
- **用户模式限制**: 仅支持用户态程序，不支持内核模块
- **系统调用依赖**: 依赖于Linux系统调用接口
- **确定性要求**: 要求程序具有一定的确定性

### 2. 性能考虑
- **存储开销**: 轨迹文件可能较大
- **内存使用**: 需要额外的内存来存储轨迹和快照
- **执行开销**: 记录模式下有一定的性能开销

### 3. 兼容性
- **QEMU版本**: 需要兼容的QEMU版本
- **目标程序**: 某些程序可能不适合RR-Fuzz
- **系统环境**: 对系统环境有一定要求
