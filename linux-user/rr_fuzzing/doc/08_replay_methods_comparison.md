【核心设计理念】
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

   旧设计：拦截 + 返回虚拟值 + 数据恢复
   新设计：真实执行 + 句柄映射 + 严格验证

   ┌──────────────────────────────────────────────────────────┐
   │  核心原则：所有系统调用都真实执行                         │
   │  - PRE-HOOK 返回 -1（不拦截）                             │
   │  - 系统调用由内核真实执行                                 │
   │  - POST-HOOK 建立句柄映射关系                             │
   └──────────────────────────────────────────────────────────┘

【Replay 方式分类】
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

根据数据来源和处理方式，新设计支持以下几种 Replay 方式：

┌────────────────────────────────────────────────────────────────────────┐
│ 1. 基于 Strace 文本的 Replay（当前实现）                               │
├────────────────────────────────────────────────────────────────────────┤
│ 数据来源：qemu-x86_64 -strace 生成的文本文件                          │
│ 解析方式：rr_syscallparser.c 解析 strace 文本格式                     │
│ 启用方式：RR_STRACE_MODE=TRUE RR_MODE=replay                          │
│ 适用场景：快速原型、轻量级 replay、调试分析                            │
│                                                                        │
│ 优点：                                                                 │
│   ✅ 人类可读，易于调试                                                │
│   ✅ 可以手动编辑 trace 文件                                           │
│   ✅ 与 QEMU 原生 -strace 兼容                                         │
│   ✅ 实现简单，易于扩展                                                │
│                                                                        │
│ 缺点：                                                                 │
│   ❌ 文本解析有开销                                                    │
│   ❌ 某些复杂参数难以解析（如 pipe 的 FD 数组）                        │
│   ❌ 不包含输出数据（read 的 buffer 内容等）                           │
└────────────────────────────────────────────────────────────────────────┘

┌────────────────────────────────────────────────────────────────────────┐
│ 2. 基于二进制 Trace 的 Replay（传统方式）                              │
├────────────────────────────────────────────────────────────────────────┤
│ 数据来源：rr_record_syscall() 生成的二进制文件                        │
│ 解析方式：直接读取 syscall_record_t 结构                              │
│ 启用方式：RR_MODE=replay RR_TRACE_FILE=xxx.dat                        │
│ 适用场景：完整的 replay、包含数据恢复、生产环境                        │
│                                                                        │
│ 优点：                                                                 │
│   ✅ 包含完整的输出数据（read buffer、stat 结构等）                   │
│   ✅ 二进制格式，解析快速                                              │
│   ✅ 支持数据恢复（可选）                                              │
│   ✅ 适合大规模 replay                                                 │
│                                                                        │
│ 缺点：                                                                 │
│   ❌ 不可读，调试困难                                                  │
│   ❌ trace 文件较大                                                    │
│   ❌ 需要严格的版本兼容性                                              │
└────────────────────────────────────────────────────────────────────────┘

┌────────────────────────────────────────────────────────────────────────┐
│ 3. 混合模式 Replay（推荐）                                             │
├────────────────────────────────────────────────────────────────────────┤
│ 数据来源：Strace 文本 + 可选的数据文件                                 │
│ 解析方式：文本解析 + 按需加载数据                                      │
│ 启用方式：RR_STRACE_MODE=TRUE + RR_DATA_FILE=xxx.data                 │
│ 适用场景：兼顾调试性和完整性                                            │
│                                                                        │
│ 优点：                                                                 │
│   ✅ Strace 文件可读，易于调试                                         │
│   ✅ 数据文件包含输出缓冲区内容                                         │
│   ✅ 按需加载数据，灵活高效                                            │
│   ✅ 可以分离关注点（控制流 vs 数据流）                                │
│                                                                        │
│ 实现：                                                                 │
│   - Strace 文件：系统调用序列、参数、返回值                            │
│   - 数据文件：read/recv 等的输出数据，按 syscall_index 索引           │
└────────────────────────────────────────────────────────────────────────┘

【新设计下的 Replay 处理方式】
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

方式 A：纯句柄映射（当前实现）
─────────────────────────────────────────────────────────────────────────

  特点：不恢复数据，只映射句柄，完全依赖真实执行

  流程：
  ┌─────────────────────────────────────────────────────────────┐
  │ PRE-HOOK                                                     │
  │ ├─ 1. 严格验证序列：syscall 必须按顺序匹配                  │
  │ ├─ 2. 映射输入句柄：recorded_fd → actual_fd                 │
  │ ├─ 3. 保存当前记录：g_current_record = record              │
  │ └─ 4. 返回 -1：让系统真实执行                               │
  │                                                              │
  │ 真实执行                                                     │
  │ └─ 内核处理系统调用，返回真实结果                            │
  │                                                              │
  │ POST-HOOK                                                    │
  │ ├─ 1. 获取真实返回值                                        │
  │ ├─ 2. 建立输出映射：recorded_handle → actual_handle        │
  │ └─ 3. 清理状态：g_current_record = NULL                    │
  └─────────────────────────────────────────────────────────────┘

  适用场景：
  - ✅ 确定性程序（每次执行结果相同）
  - ✅ 文件操作为主的程序
  - ✅ 环境一致的 replay

  示例：
    open("/etc/passwd")  → 真实打开，获得真实 FD
    read(fd, buf, 100)   → 真实读取，获得真实数据
    close(fd)            → 真实关闭

方式 B：句柄映射 + 数据恢复（未来扩展）
─────────────────────────────────────────────────────────────────────────

  特点：映射句柄 + 恢复关键输出数据

  流程：
  ┌─────────────────────────────────────────────────────────────┐
  │ PRE-HOOK                                                     │
  │ ├─ 1. 验证序列                                              │
  │ ├─ 2. 映射输入句柄                                           │
  │ ├─ 3. 检查是否需要数据恢复                                   │
  │ │    if (需要恢复数据的系统调用) {                           │
  │ │      加载记录的输出数据                                    │
  │ │      标记为 "拦截模式"                                     │
  │ │    }                                                       │
  │ └─ 4. 返回 -1 或拦截                                         │
  │                                                              │
  │ 执行/拦截                                                    │
  │ ├─ 普通系统调用：真实执行                                    │
  │ └─ 需要数据恢复的：跳过执行，直接返回记录值                  │
  │                                                              │
  │ POST-HOOK                                                    │
  │ ├─ 1. 如果真实执行：建立输出映射                             │
  │ └─ 2. 如果数据恢复：恢复输出缓冲区内容                       │
  └─────────────────────────────────────────────────────────────┘

  适用场景：
  - ✅ 非确定性 I/O（网络、随机数等）
  - ✅ 环境差异的 replay
  - ✅ 需要精确重现的场景

  需要数据恢复的系统调用：
    - read/pread/readv:     恢复读取的缓冲区内容
    - recv/recvfrom:        恢复接收的网络数据
    - getdents/getdents64:  恢复目录项数据
    - getrandom:            恢复随机数
    - gettimeofday:         恢复时间戳

方式 C：智能混合（最佳实践）
─────────────────────────────────────────────────────────────────────────

  特点：根据系统调用类型智能选择处理方式

  分类：
  ┌──────────────────────────────────────────────────────────────┐
  │ 确定性系统调用（真实执行）                                    │
  │ ├─ 文件操作：open/close/stat/lseek                           │
  │ ├─ 内存操作：mmap/munmap/mprotect                            │
  │ └─ 进程操作：fork/execve/wait                                │
  │                                                               │
  │ 非确定性系统调用（数据恢复）                                  │
  │ ├─ 网络 I/O：recv/recvfrom/recvmsg                           │
  │ ├─ 随机数：getrandom                                          │
  │ ├─ 时间：gettimeofday/clock_gettime                          │
  │ └─ 信号：sigaction/sigreturn                                 │
  │                                                               │
  │ 混合处理（部分恢复）                                          │
  │ ├─ read：文件 FD 真实执行，socket FD 恢复数据                │
  │ └─ ioctl：根据 request 类型决定                              │
  └──────────────────────────────────────────────────────────────┘

  实现：
    static bool should_restore_data(int syscall_nr, abi_long *args) {
        switch (syscall_nr) {
            case 0:  // read
                // 检查 FD 类型
                if (is_socket_fd(args[0])) return true;
                if (is_pipe_fd(args[0])) return true;
                return false;  // 普通文件，真实执行
                
            case 318: // getrandom
                return true;  // 总是恢复
                
            case 96:  // gettimeofday
                return true;  // 总是恢复
                
            default:
                return false;  // 默认真实执行
        }
    }

【完整的 Replay 流程（新设计）】
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

示例程序：
  int fd = open("/etc/passwd", O_RDONLY);  // syscall 1
  char buf[100];
  read(fd, buf, 100);                      // syscall 2
  close(fd);                               // syscall 3

记录时（RR_MODE=record）：
┌────────────────────────────────────────────────────────────────────────┐
│ syscall 1: openat(AT_FDCWD, "/etc/passwd", O_RDONLY) = 3              │
│ syscall 2: read(3, "root:x:0:0:root...", 100) = 100                   │
│ syscall 3: close(3) = 0                                                │
└────────────────────────────────────────────────────────────────────────┘

重放时（RR_MODE=replay，新设计）：
┌────────────────────────────────────────────────────────────────────────┐
│ syscall 1: openat                                                      │
│ ├─ PRE:  验证匹配 ✅，无输入 FD 需要映射                               │
│ ├─ EXEC: 真实打开，返回 FD=5 (不是记录的 3)                           │
│ └─ POST: 建立映射 {3→5}                                                │
│                                                                        │
│ syscall 2: read                                                        │
│ ├─ PRE:  验证匹配 ✅，映射输入 FD: 3→5，真实读取 FD=5                 │
│ ├─ EXEC: 真实读取，获得真实数据                                        │
│ └─ POST: 无新句柄，无操作                                              │
│                                                                        │
│ syscall 3: close                                                       │
│ ├─ PRE:  验证匹配 ✅，映射输入 FD: 3→5，真实关闭 FD=5                 │
│ ├─ EXEC: 真实关闭                                                      │
│ └─ POST: 移除映射 {3→5}                                                │
└────────────────────────────────────────────────────────────────────────┘

【不同场景的 Replay 策略】
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

场景 1：简单文件操作
─────────────────────────────────────────────────────────────────────────
  策略：纯句柄映射（方式 A）
  理由：文件内容是确定性的，真实读取即可
  实现：当前已完成

场景 2：网络程序
─────────────────────────────────────────────────────────────────────────
  策略：句柄映射 + 网络数据恢复（方式 B）
  理由：网络数据非确定性，必须恢复
  实现：需要扩展，恢复 recv 数据

场景 3：多进程程序
─────────────────────────────────────────────────────────────────────────
  策略：句柄映射 + PID 映射（方式 A 扩展）
  理由：fork/clone 的 PID 不同，需要映射
  实现：需要扩展，实现 PID 映射表

场景 4：包含随机数的程序
─────────────────────────────────────────────────────────────────────────
  策略：混合模式（方式 C）
  理由：随机数需要恢复，其他真实执行
  实现：getrandom 恢复数据，其他真实执行
