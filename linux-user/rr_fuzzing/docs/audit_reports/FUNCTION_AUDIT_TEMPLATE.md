# 函数级别审计模板

每个函数的审计将包含以下内容：

## 函数基本信息
- **函数名**: `function_name`
- **文件**: `path/to/file.c` or `path/to/file.py`
- **行号**: L123-L456
- **签名**: `return_type function_name(param1, param2)`

## 功能分析
- **目的**: 描述函数的主要功能
- **输入**: 参数说明
- **输出**: 返回值说明
- **副作用**: 是否修改全局状态、文件系统等

## 实现评估
- **复杂度**: 时间/空间复杂度
- **边界情况处理**: 是否处理 NULL、边界值等
- **错误处理**: 是否有完善的错误检查
- **性能**: 是否有明显的性能问题

## 发现的问题
- **Bug**: 潜在的逻辑错误
- **内存泄漏**: 资源未释放
- **冗余代码**: 重复逻辑
- **可读性**: 代码可读性问题

## 注释质量
- **当前状态**: 有/无注释，注释质量（简陋/中等/详细）
- **缺失**: 缺少哪些必要的说明

## 建议的标准注释

### C 函数 (Doxygen 格式)
```c
/**
 * @brief 简要描述函数功能
 * 
 * 详细描述函数的行为、用途和实现细节
 * 
 * @param param1 参数1的描述
 * @param param2 参数2的描述
 * @return 返回值描述，包括成功/失败的含义
 * 
 * @note 特殊注意事项
 * @warning 警告信息
 */
return_type function_name(type1 param1, type2 param2);
```

### Python 函数 (Google Docstrings 格式)
```python
def function_name(param1: type1, param2: type2) -> return_type:
    """简要描述函数功能。
    
    详细描述函数的行为、用途和实现细节。可以分多段。
    
    Args:
        param1: 参数1的描述
        param2: 参数2的描述
    
    Returns:
        返回值描述，包括类型和含义
    
    Raises:
        ExceptionType: 异常情况的描述
    
    Note:
        特殊注意事项
    """
```

## 改进建议
- **重构**: 如何简化或优化实现
- **重命名**: 更好的函数/变量命名
- **拆分**: 是否应该拆分为多个小函数
